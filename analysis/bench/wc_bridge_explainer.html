Мост вместо весов

Раньше каждое доказательство заново «прожёвывало» все 400.7 млрд весов: фолдило их в линейные тесты и открывало их коммит. Теперь веса аутентифицирует одноразовый enrollment, а каждое доказательство лишь перекидывает мост от него к реально использованным проекциям — ценой 2⁻⁴⁰ по надёжности. Ниже: что изменилось, из чего теперь складывается сложность, где узкие места, и живая ручка на измеренных якорях.

Доли — из admission-замеров A100 SXM4 (15.08). Оранжевым — то, что структурно удалено: онлайн-фолд весов в q_lin и открытие весового коммита. Веса больше вообще не являются строками witness (`tape.external`) — их держит enrollment. Свипы никуда не делись — поэтому их доля выросла, и они стали узким местом №1.

Зачем. В базовом протоколе веса — часть witness: каждый пруф платит за них полиномиальные фолды и открытия, линейные по числу параметров. Но веса не меняются между пруфами — платить за них каждый раз бессмысленно, если есть способ один раз зафиксировать их «навсегда» и дёшево связывать с каждым пруфом. Этот способ — коэффициентный RS-enrollment + поздний случайный мост.

Как работает мост — пять шагов

1 · Enrollment (одноразово)

Веса группируются по ширине выхода, режутся на блоки по B=15360 координат. Блок и выходная координата j дают полином: первые B коэффициентов — веса, сверху λ=1024 случайных масок (маски = приватность). Полиномы кодируются на домене N_w=32768 и связываются одним Merkle-корнем.

F(X) = Σ W·Xᵇ + Σ z·X^(B+h) · K_w=16384 · N_w=32768

2 · ρ после R1

Пруф сначала коммитит все выходы (R1), и только потом из транскрипта рождается общий на ширину коин ρ. Подгонять выходы под ρ уже поздно — на этом стоит вся конструкция. Один ρ на ширину = один набор открытий на все 72 матмула.

s_op = H(транскрипт R1) → ρ ∈ F^J

3 · P_trace в R2

Прувер коммитит P_trace = Wρ — ту самую переменную, которую едят дальнейшие ограничения (несвязанная копия = ошибка компиляции, §0.8), и проекции масок π = zᵀρ. Wρ считается «бесплатно»: он фьюзится в свип R2, который и так читает каждый вес один раз.

R2: commit(P_trace, π) → s_bind

4 · Поздние коины: α и η

Только теперь транскрипт выдаёт по случайному α на блок и q_w=40 различных точек домена η. Прувер агрегирует c = Σ α·(P_trace‖π) и отдаёт c и значения v = c(η).

c_k = Σ α·U_k · v_ℓ = c(η_ℓ)

5 · Проверка на 40 точках

Верификатор открывает enrollment-колонки в тех же η и сверяет: v_ℓ обязан равняться Σ α Σ ρ_j F(η_ℓ). Ложный P_trace — это ненулевой полином степени <K_w, зафиксированный до α и η: он выживает с вероятностью ≤ 1/p + H₄₀.

H₄₀ = C(16383,40)/C(32768,40) ≈ 8.86·10⁻¹³ ≈ 2⁻⁴⁰

Бюджет масок (ledger)

Каждый пруф раскрывает 40 точек; маски идеально прячут веса, пока раскрыто ≤ λ=1024 различных точек — итого ~25 пруфов на один enrollment, дальше re-enrollment со свежими масками (детерминированная пересверка, linking не нужен). Прувер ведёт ledger и отказывается доказывать при исчерпании.

⌊1024/40⌋ = 25 пруфов · precheck fail-closed

Мост (2⁻⁴⁰) сильнее той Ligero-части, которую он заменил (2⁻¹⁶·⁸ при τ=54): суммарная надёжность не деградировала, а по заменённой компоненте выросла. Правило масштабирования из ревью: q_w ≥ ⌈0.416·τ⌉ — q_w=40 хватает до τ=96. Оба верификатора (Python и Rust-твин) пересчитывают все коины сами и не верят ни одному значению из пруфа.

PROVE_wc = Σ свипы: cold + 4×warm ≈ 960 + 960 + 3×564 s ← 5 регенераций witness; R1/R2 несут коммит-работу — узкое место №1 + мост: C-проход по η-колонкам ≈ 580 s ← один NTT-свип по весам; Wρ уже внутри свипа R2 (≈0) + quad 677 + lin 93 + hash 23 + fresh-открытия 18 ← fresh-тесты, без изменений + egress 207 + обвязка раундов ≈ 1 900 ← merkle-финализация, компиляция пакетов; вычислено из наблюдаемой траектории + вес-фолд 3 625 + вес-открытия 1 812 ← УДАЛЕНО мостом (+ enrollment 633 s — одноразово, ÷25 пруфов ≈ 25 s/пруф)
Все числа — A100 SXM4, замеры 15.08 (admission-отчёт + живой лог прувинга). Итог на этой карте: ≈ 2 часа, из них ~60% — пять регенераций witness. Асимптотика: enrollment O(#весов) одноразово; на пруф — O(#весов) только в C-проходе моста и в чтении весов свипом R2; всё остальное — O(fresh-witness), от числа параметров больше не зависит.
