Random Projection in Routed Ligero

Why it is needed, how it compresses the witness, and a complete numerical example.

Core idea. Projection speeds up the proof by replacing a huge witness of individual scalar multiplications with one randomized fingerprint check.

1. Why the witness becomes too large

A. Three experts: only the selected route gets an activation trace

B. Why the committed witness matrix becomes large

xt | base values every product xt,iWe,i,j partial sums outputs

The commitment itself is not the expansion. The expansion occurs when each operation result is appended to the witness that is committed.

C. Projection compresses the active route

Two distinct savings. Routing removes computation traces of inactive experts. Projection then compresses the matrix-multiplication trace of the active expert. Base weights remain committed, but per-operation products are not appended for inactive routes.

2. Protocol sequence

  1. Commit first. The prover fixes the weight matrix We and claimed output yt before seeing the verifier's randomness.
  2. Sample the challenge. The verifier samples ρ ∈ FJ×1 only after those commitments.
  3. Project the weights. The prover computes Pe = Weρ ∈ FK×1 and proves that Pe was derived from the committed We.
  4. Check one fingerprint. The verifier checks ytρ = xtPe. If yt = xtWe, then ytρ = (xtWe)ρ = xt(Weρ) = xtPe.

ytρ = xtPe = xt(Weρ)

3. Numerical example

Let

X = 23 ∈ F1×2,  W = 142506 ∈ F2×3.

Ordinary matrix multiplication gives

Y = XW = 23 142506 = 17822 ∈ F1×3.

After W and Y are fixed, the verifier samples

ρ = 71119 ∈ F3×1.

The prover projects the weights:

P = Wρ = 142506 71119 = 89149 ∈ F2×1.

The verifier compares the two scalar fingerprints:

Yρoutput fingerprint = 17822 71119 = 625,  XPinput/weight fingerprint = 23 89149 = 625.

Result. Both fingerprints equal 625. A false output Y′ would pass only if its nonzero error Δ = Y′ − XW happened to satisfy Δρ = 0. Because ρ is sampled after Y′ is fixed, this occurs with probability at most about 1/|F| for a uniform field challenge.

4. What is actually saved

The original inference still computes the complete output, and projection adds linear arithmetic. The saving is inside the proof: a direct active-route trace uses Θ(K·J) nonlinear multiplication cells, while the projected check uses Θ(K) such cells plus linear work for Weρ and ytρ. The advantage is substantial for large matrices; for a tiny one-off multiplication, projection may add work rather than save it.

5. Before / after: the cost model in formulas

Baseline. "Before" is the full-witness pipeline this work started from: expert weights sit in the committed witness and every proved multiplication contributes its own witness cells. "After" is the routed-projected protocol (analysis/routed-projected-protocol.md). Both sides are priced with the same Ligero cost structure and the same code base; no unrelated optimization enters either side of the comparison.

A. One routed matmul, per token

For Xt ∈ F1×K, We ∈ FK×J:

wdir = KJ + Jproducts + outputs,  qdir = KJ  ⟹  wproj = 2K + 1H, Q, yρ,  qproj = K,

plus, once per expert and amortized over all tokens routed anywhere, K cells for the projected column Pe = Weρ, bound by a public-coefficient linear relation (no quadratic cells). The compression factors are

wdir/wproj = (KJ+J)/(2K+1) ≈ J/2,  qdir/qproj = J.

Route hiding changes the two sides asymmetrically: before, hiding et forces materializing all E expert traces (×E on the dominant term); after, the single matrix P already covers all E experts at EK cells per layer, so hiding costs ×E only on the projected weights, never on the traces.

B. Full model (Maverick), S = 1000 tokens

With L = 24 MoE layers, E = 128 experts, d = 5120, f = 8192, and three expert matrices per layer whose contraction dimensions sum to ΣKm = 2d+f (m ranges over the 3L = 72 routed matmuls):

N = L·S·(2d+f) = 442,368,000,  R = L·E·(2d+f) = 56,623,104.

The routed-projected MoE block then costs, row-exactly (ELL = 8192; the 72 yρ variables and late Freivalds auxiliaries carry their own padding):

Wroute = 2N + R + 4·72·ELL = 943,718,400,
Lroute = R + 2·72·S + 72(2E+1) = 56,785,608,  Qroute = N + 72E = 442,377,216.

Substituting this block for the ordinary weight-witness block and the E per-expert output streams gives the whole-proof ledgers (exact values printed by analysis/routed_projected_4h_model.py):

C. From cells to time

Every prover stage — witness regeneration, encoding, Merkle hashing, the linear/quadratic folds, column opening — is linear in the cells it touches, so the prove time decomposes as

tprove = Σstage i ci · ni(W,L,Q),  tbeforei / tafteri = nibefore / niafter,

with per-kernel constants ci measured, never fitted globally. Witness-bound stages therefore speed up by ×9.33, linear folds by ×5.22, quadratic folds by ×4.08. Under the per-kernel admission model the after-pipeline sums to

tprove ≤ 13,046.264 s = 3.6240 h

at S = 1000, inside the four-hour envelope; the before-pipeline is dominated by committing, encoding and folding the 888G-cell witness and admits no such envelope on the same hardware. The soundness price of the entire transformation is

εnew ≤ εLigero + 3/|F| + εhash.

Before/after in one line. The projection shrinks the witness ×9.33, the linear ledger ×5.22 and the quadratic ledger ×4.08 at a soundness cost of 3/|F| — an order-of-magnitude smaller proof workload bought with a negligible field-soundness term.
